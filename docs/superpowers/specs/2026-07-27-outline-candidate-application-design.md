# 候选大纲比较与安全应用设计

## 目标

让用户在学习库中直接查看、编辑、比较和应用候选大纲。系统必须清楚说明改了什么、为什么、会影响哪里，并始终保留旧版本。任何操作都不得自动改写正式正文。

## 核心原则

- StoryState 继续作为项目权威状态，正式大纲作为其可选字段保存；不新增第二套权威数据库。
- `plot/outline.md` 是便于用户查看的同步副本，工作流以 StoryState 中的当前大纲为准。
- 候选大纲继续走现有 candidate -> validate -> confirm -> commit 流程。
- 已有项目在用户首次使用本功能前保持不变；可将最近一次运行的 `planning.md` 作为只读的旧大纲来源。
- 候选大纲、比较报告和历史版本不改变正文、章节、人物资料或锁定事实。
- 应用大纲后只更新正式大纲，并将场景简报和短篇因果链标记为待更新。

## 数据边界

StoryState 增加可选数据：

- `outline.content`: 当前生效大纲全文；
- `outline.version`: 当前大纲版本号；
- `outline.source`: `initial`、`candidate`、`restored` 或 `legacy_run`；
- `outline.candidate_id`: 产生当前版本的候选 ID；
- `outline.updated_at`: 更新时间；
- `outline.content_hash`: 内容哈希。

候选使用既有 `story_candidates` 表，`kind="outline"`。正文保存在项目 `learning/candidates/outline-<id>.md`，metadata 保存标题、文件名、生成方式、比较摘要和模型回执的非敏感部分。

## 当前大纲来源

读取顺序：

1. StoryState 中已确认的大纲；
2. 项目最近一次有效运行的 `outputs/planning.md`；
3. 无大纲。

旧运行大纲只用于首次比较，不在读取时写回项目。用户应用候选后，系统通过 StoryState candidate commit 建立第一个正式大纲版本。

## 本地比较

本地程序按 Markdown 标题和自然段切分剧情块，并对齐标题、关键词和字符相似度。每项变化归为：

- `unchanged`: 保持不变；
- `strengthened`: 表达变化但结构位置一致；
- `added`: 新增剧情；
- `removed`: 删除剧情；
- `reordered`: 调整顺序；
- `uncertain`: 本地无法可靠判断。

报告使用普通中文显示当前内容、候选内容、变化类型、可能影响和本地判断依据。锁定事实缺失、已有正文、删除核心段落和大范围改动单独标风险。

## 模型语义复核

本地比较始终先执行，不调用模型。当存在 `uncertain` 项时，页面显示“有 N 处需要语义判断”，由用户点击后才调用现有 `planning` 角色。模型只接收：

- 当前大纲和候选大纲的相关小段；
- 本地变化项；
- 项目锁定事实摘要。

模型返回每项的语义类型、因果影响和简短说明，不生成第三份大纲。返回格式无效时保留本地报告并明确显示复核失败。

## 应用规则

- 没有当前大纲：按钮为“设为初始大纲”，可整体应用。
- 已有大纲、没有正文：允许整体应用或逐项应用。
- 已有正文：默认逐项应用；整体应用必须再次确认，且只改变后续创作依据。
- 逐项应用根据变化 ID 合并选中的新增、删除、替换和调序，其余保留当前大纲。
- 应用前执行锁定事实检查；阻断问题存在时拒绝提交。
- 成功后创建新 StoryState revision，写出 `plot/outline.md` 副本，并将 `scene_briefs`、`short_causal_chain` 标为 `stale`。
- 恢复历史版本也创建一个新 revision，不删除之后的历史。

## 创建作品时的学习选择

全局候选写法继续独立保存。创建作品向导的完成摘要展示已确认候选，用户可勾选“创建后应用”。项目创建完成后使用现有 adoption API 生成第一版创作蓝图；未勾选的候选仍留在全局学习库。

首版只展示最多 12 条已确认候选，避免向导过长。低置信度、已拒绝和竞品禁用项不进入列表。

## 页面设计

“学习库 -> 作品应用”增加首屏可见的“大纲版本”工作区，不再藏在“高级学习资料”中：

1. 当前状态条：当前大纲来源、版本、正文状态和一句风险说明。
2. 生成区：微调要求、生成按钮和可持续更新的执行状态。
3. 候选列表：候选标题、时间、状态、查看与编辑入口。
4. 比较视图：顶部统计，下面按变化卡片展示；卡片提供复选框，不嵌套卡片。
5. 固定操作区：应用所选、整体应用、放弃候选。
6. 历史版本：默认折叠，显示版本、来源、时间和“恢复为新版”。

文案避免“artifact”“diff”“semantic”等技术词，统一使用“当前大纲”“候选版本”“变化”“需要模型判断”。所有异步操作显示开始、处理中、完成或失败，并保留可重试入口。

## 风险控制

- 任何应用都不修改 `manuscript/story.md` 或章节正文。
- StoryState revision 不匹配时拒绝应用，提示用户刷新后重新比较。
- 候选文件丢失或哈希变化时拒绝应用。
- 锁定事实从当前大纲中消失时阻断应用。
- 参考资料原文、人物、设定和连续表达不进入大纲应用上下文。
- 大纲超过 100,000 字符时拒绝，模型复核上下文总长度限制为 30,000 字符。

## 验收标准

- 用户能在页面查看并编辑候选大纲，不需要打开文件夹。
- 无当前大纲时可以设置初始大纲；有当前大纲时能看到结构化变化。
- 用户可逐项或整体应用，旧版本始终可恢复。
- 已有正文时页面明确说明正文不会改变。
- 本地比较不调用模型；只有用户确认语义复核时调用 `planning`。
- 应用后工作流加载当前正式大纲，派生资料变为待更新。
- 现有项目、正文、运行记录、模型配置和学习库数据不因迁移改变。
