# 有证据的文笔候选与基础文笔设计

## 目标

把优秀参考作品中的可迁移文风整理为用户可理解、可确认、可撤销的基础文笔规则，同时不增加模型调用、不模仿原句，也不改写已有正文。

## 数据流

1. 参考资料全文分析继续使用现有 `reference_analysis` 分窗和 `reference_synthesis` 汇总角色。
2. 分窗结果保留带文笔类别的 `style_evidence`，并明确排除钩子、事件密度、反转和剧情兑现；旧版窗口不会作为新版文笔证据复用。同一次汇总最多返回四条通用文笔规则。
3. 只有参考作品和爆款样本可以生成 `style_rule` 候选。汇总遗漏窗口编号时，只按相同文笔类别找回真实原文证据；仍无可定位原文证据的规则不保存。
4. 候选默认是待确认状态。确认只认可分析，不会改变作品。
5. 用户选择作品并应用后，规则合并进该作品的 `prose_baseline` 新版本。重复规则不重复写入。

## 页面

候选写法页把文笔与剧情写法分区。文笔候选展示规则、适用场景、避免方式、资料来源和原文证据，按钮分别为确认、加入作品和拒绝。

作品应用页始终展示当前基础文笔，包括项目题材、视角、语调、系统默认规则和已确认的样本规则。没有样本规则时也不得隐藏。历史版本继续使用现有恢复入口。

## 边界与回滚

- 不新增数据库表，不新增模型角色，不改变密钥或模型绑定。
- 不把作者身份、专名、设定、情节包装或独特表达写入基础文笔。
- 不修改 StoryState、正式大纲、候选稿或正式稿。
- 恢复旧版 `prose_baseline` 即可回滚已应用文笔；候选本身保留确认与拒绝记录。
- 老模型返回缺少 `style_profile` 时按空文笔候选处理，原有剧情分析继续完成。
