# 参考资料模型分析断点续跑设计

## 目标

模型全文分析在任意文本窗口或最终汇总阶段失败后，重新运行只处理缺失或失效的部分。窗口长度、数量和边界可以随正文及分窗规则变化，系统不按固定窗口编号盲目复用。

## 窗口身份

每个成功的模型窗口结果继续保存为现有 `model_claim` 节点，并增加以下校验信息：

- 原文版本 ID 与内容哈希，用于记录结果来源；
- 分窗分析版本；
- 窗口起止位置；
- 窗口正文哈希。

续跑时先按当前正文重新分窗，再逐个核对。分析版本、资料类型和窗口正文哈希必须一致，结果结构也必须仍然有效。原文版本只记录来源，不会让整篇缓存一起失效；新版本里正文完全相同的窗口可以复用。窗口重新切分后，只有正文仍完全一致的窗口可复用，变化窗口重新调用模型。

## 当前任务兼容

旧 `model_claim` 没有完整校验信息。仅当资料只有一个原文版本、窗口编号和起止位置完全一致、结果仍通过当前结构及中文校验时，系统复用每个窗口最新的一条旧记录，并补齐校验信息。《河清海晏》当前符合这些条件，因此已完成的 9 个窗口可以用于本次续跑。

## 执行流程

1. 读取当前原文并动态生成窗口清单。
2. 查找并校验每个窗口的持久化结果。
3. 将有效结果按当前窗口顺序加入本次汇总输入。
4. 只调用缺失、失败或失效的窗口，并在每个窗口成功后立即保存。
5. 所有窗口齐全后运行最终汇总。若汇总失败，下次复用全部窗口，只重新汇总。

备用模型或模型路由改变不会让已经完成的窗口失效，因为每个窗口结果都保留实际调用记录，后续可以由另一条可用路由完成剩余窗口。原文、分窗边界、窗口内容或分析版本变化会使对应缓存失效。

## 页面反馈

任务状态增加已复用数量和当前窗口。用户会看到“已复用 9 个窗口，正在分析第 10 个”，而不是误以为重新从头调用。失败提示明确说明再次运行会保留已完成窗口。

## 验证

- 动态窗口列表中只复用身份完全匹配的窗口；
- 任意窗口失败后，下一次不再调用已完成窗口；
- 最终汇总失败后，下一次不再调用任何正文窗口；
- 旧单版本资料可以复用已有窗口，存在多个原文版本时不冒险复用旧记录；
- 任务 API 和页面展示复用数量及当前窗口。
