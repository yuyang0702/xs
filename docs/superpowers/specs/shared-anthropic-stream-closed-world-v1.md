# Shared Anthropic stream protocol, version 1

The response-side stream boundary consolidates lifecycle decisions currently split across the adapter, exact SSE decoder, terminal-byte heuristic, usage projection and HTTP interruption handling. Request assembly, route selection, retry budgets, model-visible text, literary validation and formal promotion remain unchanged.

The owning protocol module uses a closed state/event registry. Its transition operation is the production operation exercised by generated matrix tests. Content ownership, cumulative usage and payload validation remain structural guards in that operation; invalid payloads transition to a typed protocol terminal. A retained Provider error permits only secondary diagnostics from later events. A valid success terminal permits keepalive and transport-tail diagnostics; a subsequent Provider error remains fatal. Unsupported semantic continuations and unknown events use an explicit versioned fail-closed policy, not a generic transport classification.

Semantic completion, capture proof and clean transport closure are separate. A valid message_stop proves semantic completion. Only an explicit True from the raw-byte persistence callback acknowledges capture; metadata-only callbacks returning None or False cannot grant capture completeness. The production probe writer uses exclusive creation, flush/fsync and exact hash verification. The legacy capture transport_complete field continues to expose terminal-byte completeness to existing consumers. Clean EOF is separate from timeout/cancellation. Post-success timeout/cancellation cannot revoke a complete result; pre-terminal interruption cannot grant success. An error never grants successful Message authority.

The existing terminal record gains optional provider_stream_error (StreamProviderErrorEvidenceV1) and stream_outcome_v1 (ProbeStreamOutcomeEvidenceV1). These are closed, privacy-safe enums/counts/hashes bound to the case, request, route and captured entity. Records without these fields retain V1 reload semantics without migration. Nested diagnostic records are copied on read. The response ModelResponse remains exactly replay-equivalent; tail diagnostics stay outside model-visible content. Client close faults enter the same owner before the terminal record is sealed. A consumed failed nonce cannot be dispatched again.

Usage-only receipts intentionally accept historical abbreviated usage envelopes. They share the protocol event classification and cumulative reducer but do not claim semantic Message acceptance, and never admit usage after message_stop or Provider error. Their existing source indices and receipt hashes remain stable.

The migration preserves all existing partial work in an external byte-exact baseline. The adapter delegates the old aggregation entry to the owner; HTTP delegates the Anthropic response resolution while keeping other protocols unchanged. Decoder framing remains framing, with ordered typed invalid events rather than semantic error precedence hidden in its own booleans. Duplicate protocol decision paths are removed or delegated only with parity evidence.

Offline acceptance comprises every registered state/event cell, shape and ownership guards, pre/post-terminal faults, all discoverable exact historical captures, baseline-green regressions, request byte parity, existing Provider and related Runtime suites. Independent reviewers and Strict L3 precede commit. A failed closed-world proof stops the campaign with architecture redesign required. No real request is permitted before the fresh frozen-head authorization and all Master gates.

Rollback is the preserved task baseline and Git history, not reset/discard of the shared dirty worktree. No live StoryState, Canon, project database, manuscript or active checkpoint is modified by offline validation.
