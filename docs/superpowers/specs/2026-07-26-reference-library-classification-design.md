# 参考资料学习库分类与用途路由设计

## 目标

让参考资料在项目、平台和资料数量增加后仍可识别、筛选和安全复用，并让“内容类型”真正决定资料进入哪一种分析或检查流程，而不把内容类型误当成作品文风。

## 已确认原则

- 内容类型表示“这份资料拿来做什么”，不表示“作品要写成什么风格”。
- 系统自动推荐内容类型，用户可以在导入前修改，也可以在导入后修改。
- 无法可靠判断时默认使用“参考作品”，不得阻止导入。
- “竞品作品”必须由用户明确选择，不进行自动判定。
- 原始资料属于全局学习库；关联作品用于筛选和默认推荐，不锁死资料，也不直接改变作品。
- 从资料提炼出的机制仍是候选项，只有用户采纳到具体作品后才参与该作品的写作。
- 平台规则不能被当作文风样本；平台规则只进入对应平台的终审检查。
- 不新增模型调用，不因自动分类消耗 Token。

## 字段与取值

每条参考资料新增三个兼容字段：

| 字段 | 取值 | 默认值 | 用途 |
|---|---|---|---|
| `platform` | 自由文本，界面提供常用平台选项 | 空值，显示“未指定平台” | 展示、筛选、平台终审路由 |
| `content_type` | `reference_work`、`platform_rule`、`popular_sample`、`writing_tutorial`、`competitor_work` | `reference_work` | 分析与使用路由 |
| `project_id` | 已存在作品 ID 或空值 | 空值 | 展示、筛选、默认推荐范围 |

内容类型的中文显示名：

- `reference_work`：参考作品
- `platform_rule`：平台规则
- `popular_sample`：爆款样本
- `writing_tutorial`：写作教程
- `competitor_work`：竞品作品

删除作品时不删除全局资料，只将该资料的 `project_id` 清空。

## 自动推荐

自动推荐是本地、确定性的文本判断，输入为资料标题、公开网址和正文前部，不调用模型。

判断优先级：

1. 出现投稿要求、平台规范、禁止事项、字数限制等强规则信号时，推荐“平台规则”。
2. 出现写作方法、教程、技巧、案例讲解等教学信号时，推荐“写作教程”。
3. 出现爆款、高赞、热门、阅读量等样本信号时，推荐“爆款样本”。
4. 其余内容推荐“参考作品”。

平台从用户选择、标题、网址域名和正文前部推断；用户选择优先于推断。首版提供知乎、番茄、公众号、晋江和“其他/未指定”，同时允许保存自由文本。

界面显示推荐结果和“系统推荐”标记。用户一旦手动选择，提交值即为最终值。竞品作品只出现在手动选项中。

## 内容类型的工作流作用

| 内容类型 | 本地诊断 | 本地提炼/模型深度分析 | 平台终审 | 原创与版权比对 |
|---|---|---|---|---|
| 参考作品 | 通用全文诊断 | 结构、节奏、叙事和表达机制 | 否 | 否 |
| 平台规则 | 规则文本诊断 | 提取硬性要求，不提炼文风 | 同平台作品发布前使用 | 否 |
| 爆款样本 | 通用诊断并突出标题、前三行、前 500 字和钩子 | 提炼留存、节奏和转折机制 | 否 | 否 |
| 写作教程 | 通用诊断 | 提取方法和检查规则，不学习教程文风 | 否 | 否 |
| 竞品作品 | 通用全文诊断 | 差异化候选机制 | 否 | 是 |

首版路由约束：

- 现有“本地诊断”接口保持可用，报告增加资料类型和分析重点元数据。
- 本地提炼与模型深度分析按类型选择提示或本地提炼重点；现有候选、证据和人工采纳机制保持不变。
- `comparison_sources(project_id)` 只返回“竞品作品”，并优先返回未关联或关联当前作品的资料，避免普通参考作品被误用于版权相似检查。
- 平台终审只读取平台一致的“平台规则”；没有匹配规则时沿用现有终审，不阻塞写作。
- 内容类型修改不自动重新调用模型。已有模型结果标记为需要复核，用户再次点击深度分析时才更新。

## 循环题材的有意重复保护

本地重复检测继续负责找出完全重复表达和相同功能段落，但不得把提示文案当作自动修改命令。

- 所有重复结果保持 `review`，不得自动删除或改写正文。
- 项目具有循环、轮回、重生复现、梦境复现等结构信号时，将重复项标记为“需要判断是否为有意复现”。
- 第二次出现附近存在人物状态、场景变量、新信息或后果变化时，报告增加 `intentional_repetition_candidate=true`，修复目标改为检查新叙事作用，而不是直接要求删除。
- 本地无法确定第二次是否承担新作用时，只把命中位置及邻近上下文交给终审模型复核；不因此触发参考资料模型深度分析或全文重审。
- 普通作品仍保留原来的字面重复提醒。

首版使用本地可解释信号判断附近变化，包括时间/次数标记、转折词、人物动作差异、命名实体差异及 LTP 状态变化；没有 LTP 时回退到标准规则。

## 爆款样本专用分析

“爆款样本”必须启用实际分析能力，不得只作为分类名称。该分析面向导入的参考样本，目标是形成候选机制；它不同于作品终审，后者面向用户作品并决定是否达到发布标准。

本地爆款分析输出以下分区：

- 标题：人物或身份、异常、冲突、结果、信息差、长度、空泛夸张词、正文兑现线索。
- 前三行：逐行长度、人物、异常、处境、悬念和信息密度。
- 前 300～500 字：人物、异常、目标、冲突、未解决问题和继续阅读理由。
- 中段：事件密度、新信息间隔、场景变化、状态变化、连续解释和背景堆积。
- 转折：位置、前置铺垫、判断变化及后续结果。
- 结尾：显式问题兑现、新问题、人物状态变化、主要冲突和标题承诺。

输出必须包含可计算指标、带偏移量的证据和需要人工复核的候选项。本地程序与 LTP 优先完成；只有用户主动点击“模型深度分析”时，才把不确定候选位置交给模型。爆款本地分析本身不消耗 Token。

## 候选机制证据升级

本地提炼不再为每个约 5000 字窗口固定生成一个宽泛标签，也不再默认用窗口第一句充当证据。

- 每个窗口可以产生零到多个机制。
- 机制按标题、开头、前 500 字、中段、转折、高潮、结尾标注结构位置。
- 每个机制必须保存机制名称、观察事实、分析解释、原文证据及偏移量、迁移方法、不适用条件和置信度。
- 证据必须包含触发该机制判断的实际句段；无法找到支持证据时不生成机制。
- 低置信度机制必须先“确认分析”或经过模型复核，不能直接采纳。
- “确认分析”只确认候选；“采纳到作品”继续通过现有项目采纳和新版创作蓝图流程，不直接写正文。
- 修改资料类型后，既有机制标记为待复核，不自动调用模型。

## 界面

导入区增加：

- 平台选择框，默认“自动判断”。
- 内容类型选择框，默认“自动判断”，并展示系统推荐结果。
- 关联作品选择框，默认“不关联作品”。

资料列表上方增加：

- 关键词搜索：匹配资料名称、平台和内容类型显示名。
- 平台筛选。
- 内容类型筛选。
- 关联作品筛选。

列表项显示：

```text
知乎悬疑惊悚脑洞
知乎 · 参考作品 · 关联《全城都说我有一个女儿》
14,245 字符 · 1 个版本
```

资料详情允许修改平台、内容类型和关联作品。修改仅改变资料元数据和后续用途，不修改原文，不自动采纳机制，不改变作品文风。

## API 与数据迁移

- 导入接口接受可选的 `platform`、`content_type`、`project_id`。
- 新增资料元数据更新接口，只允许修改上述三个字段。
- 列表接口继续返回全部资料，并返回新增字段及推荐信息；筛选先在前端完成，不增加不必要的查询接口。
- 数据库使用幂等迁移为 `reference_sources` 增加字段。旧库重复启动不会失败。
- 旧资料迁移后为 `reference_work`、空平台、空作品关联，保证旧行为可继续使用；版权比对范围变窄是本功能明确要求的安全修正。
- 导入重复正文时返回原有资料，不静默覆盖原有分类；界面提示资料已存在，用户可在详情中修改元数据。

## 错误处理

- 关联不存在或已删除的作品时返回可理解的校验错误。
- 未知内容类型返回 422，不写入资料。
- 自动判断失败时回退为“参考作品/未指定平台”，不阻止导入。
- 迁移保留所有原文、版本、分析缓存、学习节点和项目采纳记录。

## 测试与验收

必须先写失败测试，再写实现。验收标准：

1. 新建数据库和旧数据库都能幂等获得三个新字段，旧资料及版本不丢失。
2. 平台规则、写作教程和爆款样本的典型文本能由本地规则正确推荐；普通小说回退为参考作品；系统永不自动推荐竞品作品。
3. 用户手动选择会覆盖推荐结果，导入后可修改。
4. 不存在的内容类型和作品关联被拒绝，数据库无部分写入。
5. 搜索及三个筛选器可以组合使用，空结果有明确提示。
6. 普通参考作品不再进入原创比对；竞品作品按全局或当前作品关联进入。
7. 平台规则只提供给同平台作品终审；无匹配规则时旧终审流程保持可用。
8. 类型修改不调用付费 API、不改原文、不自动采纳学习机制。
9. 既有参考资料、学习库、终审和完整测试套件全部通过。
10. 循环结构中的重复锚点在邻近状态发生变化时被标为有意复现候选，普通无变化重复仍被提示。
11. 爆款样本报告覆盖标题、前三行、前 500 字、中段、转折和结尾，且全程不调用模型。
12. 本地机制证据来自实际触发句段；没有证据的泛化机制不生成，低置信度机制不能直接采纳。

## 风险与控制

- **自动误判**：推荐可见且可修改；低置信度直接回退参考作品。
- **旧资料退出版权比对**：这是为了避免将普通学习样本全部当成竞品；用户可把需要比对的旧资料改为竞品作品。
- **平台规则解析不完整**：首版只作为附加终审上下文，不覆盖现有终审和质量闸门。
- **跨项目污染**：关联作品只影响默认范围；采纳仍由现有项目级采纳记录控制。
- **重复资料分类冲突**：不自动覆盖，返回已有资料后由用户显式修改。

## 非目标

- 不自动模仿任何参考作品文风。
- 不自动将提炼结果应用到作品。
- 不使用模型判断资料类型。
- 不新增标签系统、文件夹层级或复杂权限系统；首版先使用平台、内容类型、关联作品和关键词搜索。
