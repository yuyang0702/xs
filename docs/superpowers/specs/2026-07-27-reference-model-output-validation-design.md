# 参考资料模型分析输出校验设计

## 问题

参考资料模型分析目前只验证返回内容能否解析为 JSON，没有验证 JSON 是否符合窗口分析或全文汇总协议。模型返回合法但结构错误的对象时，流程仍会完成，前端因缺少 `mechanisms` 字段而显示“得到 0 个候选写法”。

## 方案

沿用现有 `reference_analysis` 和 `reference_synthesis` 角色及其配置备用模型，不增加模型角色或数据表。

1. 窗口分析必须返回对象，且包含协议规定的六个列表字段。列表项必须是带正文位置、事实和解释的对象。
2. 全文汇总必须返回 `mechanisms` 列表和 `attraction_map` 对象。候选写法必须包含名称、支持窗口和可执行的迁移说明。
3. 主模型返回空内容、无效 JSON 或协议不合格内容时，统一调用该角色已经配置的备用模型一次。
4. 备用模型仍不合格时，任务明确失败并显示具体阶段与原因。已经保存的窗口分析和本地结果继续保留。
5. 窗口提示要求少量高价值证据，避免重复解释占满输出；窗口输出上限从 4096 降到满足结构化证据所需的范围。全文汇总仍保留足够预算。
6. 前端只有在收到经过协议校验的结果后才显示候选数量；失败不得显示“完成，0 个候选写法”。

## 数据与兼容性

不修改已有参考资料、学习节点、采纳记录或模型绑定。旧的窗口分析记录继续保留；重新分析会产生新的有效汇总结果。候选写法仍需用户逐条确认和采纳，不会自动进入作品或修改正文。

## 验收

- 合法 JSON 但窗口结构错误时会调用 `reference_analysis` 备用模型。
- 合法 JSON 但汇总结构错误时会调用 `reference_synthesis` 备用模型。
- 主备模型均返回错误结构时，任务失败并说明协议错误。
- 合法的空候选列表可以成功，但必须同时返回完整的 `attraction_map`；界面解释为“未形成可采纳候选”，不冒充模型未运行。
- 已有模型路由、候选采纳和本地提炼测试保持通过。
