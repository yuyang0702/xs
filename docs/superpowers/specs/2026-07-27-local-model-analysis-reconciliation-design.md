# 本地与模型分析合并展示设计

## 目标

让用户在同一条候选写法上看清本地程序发现了什么、模型是否复核、模型是否新增了本地未发现的内容，以及最终是否已由用户确认。所有面向用户的模型结论必须使用简体中文，页面不得直接展示未中文化的模型字段。

## 数据与判断

- 继续使用现有 `learning_nodes.data_json`，不新增平行表或模型角色。
- 本地提炼节点记录 `analysis_origin=local` 和原始本地置信度。
- 全文模型分析开始前复用本地全文提炼结果。模型逐窗先独立分析正文，再复核本地信号，避免只附和本地候选。
- 全文汇总时向模型提供本地候选 ID。模型返回 `local_match_id`、`model_verdict` 和中文复核理由。
- 命中本地候选时更新同一节点的 `model_review`，不再生成重复卡片；没有匹配时保存为 `analysis_origin=model` 的模型新增发现。
- 本地分数和模型判断分别保存。页面只显示“高、待复核、意见不同”等可理解结论，原始分数放入折叠的判断依据。
- 用户确认、拒绝和应用状态保持现有逻辑，模型不得自动代替用户采纳。

## 中文约束

- 窗口分析和全文汇总提示明确要求所有解释性字段使用简体中文。
- 后端校验核心模型字段；英文结果视为无效模型输出，进入现有备用模型流程或返回中文错误，不进入候选区。
- 对历史英文记录，界面显示中文说明和重新分析提示，不直接展示英文模型内容。
- 学习库相关栏目和来源类型改用中文名称，技术枚举仅在折叠详情中出现。

## 页面

- 候选写法卡片顶部显示来源：`本地提炼`、`模型新增`、`本地发现 + 模型确认`、`本地与模型意见不同` 或 `等待模型判断`。
- 卡片显示来源资料、分析范围、综合判断和证据数量；不再把模型自报百分比当作最终可信度。
- 增加来源筛选，但不增加新的分析页面。
- 资料详情用三段简短说明区分本地诊断、本地提炼和模型全文分析。
- 剧情吸引力报告明确标记为模型全文分析结果。

## 边界

- 本地确定性规则仍然不调用模型。
- “模型深度分析”仍覆盖全文，并允许模型新增本地未发现的内容。
- 本次不做反馈训练、统计校准或新的付费模型调用。
- 不自动修改已生成正文、正式大纲或已采纳内容。

## 验证

- 本地节点能被识别为本地结果。
- 模型确认本地候选时只保留一条节点。
- 模型新增发现能独立保存并明确标注。
- 英文模型结果不能进入面向用户的候选区。
- API 返回来源资料、判断来源和综合状态。
- 桌面和手机页面能清楚展示来源、证据和操作按钮且无横向溢出。
